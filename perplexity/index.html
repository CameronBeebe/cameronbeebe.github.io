Perplexity, cross-entropy, and bits per byte

Perplexity measures how surprised a language model is by a piece of text. The model assigns a probability to each next token; we average how wrong those guesses were (log loss), then turn that average into a count: roughly how many options the model is torn between. Lower is better.

perplexity = exp(average log loss)

A perplexity of 1 would mean it always knew what came next. A perplexity of 32 is like guessing among 32 equally likely options — try the slider below. One catch: raw perplexity is not a fair way to compare models that cut text into different tokens. Bits per byte is, because it asks how many bits were needed to describe the same letters.

This slider is not a trained model. It just shows the same number in three units: the count (perplexity), the bits, and the average probability of a correct guess.

These scores were measured on a CPU, on short passages, with public checkpoints of GPT-2 small, DistilGPT-2 (same tokenizer as GPT-2), and SmolLM2-135M (a different tokenizer). Why bits per byte

A tokenizer is how a model chops text into pieces. A model that makes more, shorter tokens gets more (easier) guesses, so its raw perplexity can look better for bookkeeping reasons. Bits per byte keeps the same surprise in the numerator and divides by the letters themselves — the UTF-8 bytes — so two models can be compared on the same text.

That is the zucchini and WikiText lesson above: the ranking or the size of the gap can change once you stop dividing by each model’s own token count. A table that holds one joint surprise fixed and only changes the unit is in For the math-curious.

Two ways to score a guess

Log loss is “how shocked you were at what actually happened.” It depends only on the probability you gave that outcome, which is why it converts cleanly into bits and perplexity. The Brier score is the squared distance between your forecast and the truth. Both rules are honest: the unique way to get the best expected score is to report the probabilities you actually believe.

Brier score = squared distance between the forecast and the truth

They still disagree in feel. Log loss has no ceiling — a near-zero probability on the realized token is punished without bound. Brier is capped (at 2) and barely moves once that probability is already tiny. The sliders below grade the same belief, report, and outcome both ways.

For the math-curious

The usual training objective is the average log loss, also called cross-entropy:

\[ \mathrm{CE} = -\frac{1}{N}\sum_{t=1}^{N}\log p(x_t\mid x_{<t}), \qquad \mathrm{PPL} = e^{\mathrm{CE}}, \qquad \mathrm{BPB} = \frac{N\cdot\mathrm{CE}}{(\ln 2)\, B}. \]

Under a believed distribution \(q\), expected log loss and expected Brier split into an uncertainty term that depends only on \(q\), plus a divergence that is zero only when the report equals the belief:

\[ \mathbb{E}_q[-\log p(Y)] = H(q) + D_{\mathrm{KL}}(q\|p), \qquad \mathbb{E}_q[\|p-e_Y\|^2] = \big(1-\|q\|^2\big) + \|p-q\|^2. \]

When the truth is a single outcome (a one-hot vector), KL to that truth is just the log loss. The language-model Brier on a token is the same squared distance over the full vocabulary, \(\|p-e_y\|^2=\|p\|^2+1-2p_y\), always between 0 and 2. On this page it is computed from the full softmax, not from the top-5 list. The binary slider uses the two-class form \(2(p-y)^2\), so it is the same formula with two classes instead of 50,000.

How the numbers were computed

On 23 November 2026, America/Denver, a CPU box ran compute_scores.py with PyTorch 2.15.0+cpu and Transformers 5.24.0. Checkpoints: gpt2 (124,439,808 parameters, vocab 50,257), distilgpt2 (81,912,576, same tokenizer), and HuggingFaceTB/SmolLM2-135M (134,515,008, vocab 49,152). Each text was encoded with add_special_tokens=False — none of these tokenizers prepends BOS — and scored in one float32 forward pass. The first token is shown but not scored. Bits per byte uses only the UTF-8 bytes of the concatenated scored tokens. Scripts are in scripts/. The toy trigram is an interpolated 3-gram over UTF-8 bytes, trained on the Salesforce WikiText-2 raw train split (10,914,845 bytes).
